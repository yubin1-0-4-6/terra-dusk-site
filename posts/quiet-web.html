把博客搬回自己手里

在别人的时间线上写作，就像在租来的房子里钉钉子——你总要先想一想，这面墙算不算你的。

白鎏 7 分钟阅读 写了一晚

我上一个博客建在一个很流行的平台上。界面漂亮，写完点发布就行，还有统计、评论、推荐。唯一的缺点是：每次平台改版，我的文章都会重新排版一次；每次我想加一行自己的代码，都要跟编辑器搏斗。

搬走的念头出现过很多次，都被「等有空的」压下去了。直到今年春天，那个平台宣布关闭旧版编辑器。我的三十几篇文章里，有九篇的脚注全部错位。那天晚上我决定：这面墙，我自己砌。

最小的配置

我给自己定了三个要求：打开快、能活十年、不需要维护。所以没有数据库，没有 CMS，没有构建步骤。文章就是 HTML 文件，样式就是一份 CSS，首页那颗地球是一段原生 WebGL。

  • 纯静态文件：文章是 HTML，样式是一份 CSS，首页那颗地球是一段原生 WebGL；
  • 托管在 GitHub Pages：免费、自动 HTTPS、自带 CDN，构建不用我操心；
  • 本地直接手写 HTML，没有构建脚本，也没有依赖升级；
  • 发布就是 git push，回滚就是 git revert。
git add -A
git commit -m "新文章"
git push

这就是全部。没有插件，没有依赖升级，没有「更新后站点白屏」的深夜。我第一次感觉到，网站可以是一件不会坏的东西。

关于速度

首页总大小约 1.6 MB，其中 90% 是地球的四张贴图。我犹豫过要不要把它们换成程序化生成的噪声，但试了两版都不好看。最后接受这个成本，并把贴图做了延迟加载：文字先出现，球体随后淡入。

没有 cookie 横幅，没有统计脚本，没有第三方字体阻塞——除了 Google Fonts，它会在加载失败时安静地退回系统字体。一个博客不需要知道你是谁。

写到没有读者

搬过来之后，阅读量掉了八成。推荐流量消失以后，每篇文章的读者从「几千个路过的人」变成了「几十个真正打开的人」。奇怪的是，我写得更认真了。

没有读者的写作，反而更接近写作本身。你不再为一个标题的点击率负责，只为一句话是否准确负责。偶尔收到一封邮件，说某一段他读了两遍——这比任何数据都让人高兴。

这大概就是自留地的意义：它不会让你更红，只会让你更久。
