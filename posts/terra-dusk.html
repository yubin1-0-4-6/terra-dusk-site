我用一个球体装下了整颗地球

首页那颗会转的地球，其实没有一丁点三维几何。它是一张铺满屏幕的四边形，和一个逐像素求解的球面方程。

白鎏 9 分钟阅读 WebGL · GLSL

我很喜欢那种「看起来用了很多资源，其实只用了很少资源」的东西。首页这颗地球就是其中之一：它没有模型文件，没有贴图球，没有光照系统，甚至没有相机。整个画面由一个三角形带绘制出来——四个顶点，两张三角形，而已。

没有几何体的球

关键在于：球体不需要被建模，它可以被算出来。对屏幕上的每一个像素，把它换算成以球心为原点、半径为一的坐标 p。只要 |p| < 1，这个像素就在球内，而它的深度可以由单位球方程直接得到。 

vec2 p = (gl_FragCoord.xy - center) / (0.5 * uSize);
float z = sqrt(max(1.0 - dot(p, p), 0.0));
vec3 n = vec3(p, z);          // 指向观察者的球面法线

n 就是这一点的法线：屏幕上的位置决定经度和纬度，z 决定它离镜头有多近。边缘处 z 趋近于零，法线越来越侧向，正好形成真实球体的轮廓衰减。没有透视矩阵，没有顶点插值，只有每个像素的一点算术。

把地图贴上去

有了法线，投一张等距圆柱投影（equirectangular）的地球贴图就只是两个反三角函数。先按地轴倾角转一下，再按自转时间转一下，得到「地图空间」里的方向 m： 

float lat = asin(clamp(m.y, -1.0, 1.0));
float lon = atan(m.x, m.z);
vec2 uv = vec2(lon / 6.2831853 + 0.5, 0.5 - lat / 3.1415926);

注意 0.5 - lat / π：图片的第一行是北极，而纹理坐标的零点也在上方，两边对齐之后地球才不会上下颠倒。这类小地方错了不会报错，只会让整个画面悄悄变得不对劲。

让城市在夜里亮起来

昼夜不是两张贴图的淡入淡出，而是同一束光的结果。太阳方向 L 与法线的点积决定这一点的明暗，再用一个很窄的 smoothstep 把它切成夜面、晨昏线和白昼： 

float ndl = dot(n, L);
float day = smoothstep(-0.10, 0.30, ndl);
surf += vec3(1.0, 0.58, 0.26) * city * (1.0 - day) * uLights;

夜面的城市灯光用一张单独的贴图，只取亮度，乘上暖橙色。因为 day 是连续过渡的，灯光会沿着晨昏线一点点浮现，而不是突然被打开。

云层是另一张带透明通道的贴图。它比地面转得稍微快一点，采样时再朝太阳方向偏移一点点，就得到了云投在地面上的影子。这个偏移只有几个像素，但它让整颗星球突然有了厚度。

一点余量

最难的部分不是数学，是克制。最早的版本里我加了镜头光晕、色差、胶片颗粒和一堆闪烁的星星，结果像一张过度后期的太空壁纸。后来一项一项删掉，只留下大气边缘、一点暖色的晨昏线和一层很淡的暗角。

最后一步是色调映射。所有光照在线性空间里算，输出前过一遍 ACES 曲线，再做伽马编码。高光不会直接烧成死白，蓝色的大气边缘也能保留层次——那颗球看起来「有空气」，很大程度上是因为这一行。

地表贴图来自 NASA 的 Blue Marble 系列，通过 three.js 的示例资源取得。整个渲染器不到四百行，没有依赖，在手机上也能跑满帧。如果你也想做一颗，从这里开始就够了。
